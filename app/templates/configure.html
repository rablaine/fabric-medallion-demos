Configure the {{ vertical.name }} Data Estate

Set your deployment parameters, then download a customized package that you can run with your own Azure CLI credentials.

What deploy.cmd does, step by step

You fill in the form above, click Download Deployment Package, and get a zip with your settings baked in. Inside the zip is deploy.cmd. Running it prompts for your Azure account + subscription, then deploys an end-to-end {{ vertical.name|lower }} data estate in one shot (typically 25-40 minutes). Expand any step below for the details.

Stand up the Azure resource group and core services

One Bicep deploy creates everything in your subscription:

  • Resource group in your chosen region
  • VNet (10.50.0.0/16) with two subnets — one delegated to the Fabric VNet Data Gateway, one for the SQL Private Endpoint
  • Azure SQL serverless Gen5, AAD-only auth, with the retail OLTP schema and change tracking applied in the background
  • Private Endpoint to the SQL server in the PE subnet, plus a privatelink.database.windows.net private DNS zone linked to the VNet
  • ADLS Gen2 storage account with raw/ and curated/ containers (supplier Parquet, marketing CSV, weather data all land here)
  • Azure Functions (Flex Consumption / FC1) app that emits synthetic clickstream — later wired straight to the Fabric Eventstream's CustomEndpoint (no Azure Event Hubs namespace needed)
  • Microsoft Fabric F8 capacity with you assigned as admin
Create a service principal for Fabric ↔ SQL mirroring

Fabric VNet gateway connections require a service principal (workspace identity isn't accepted). The script:

  • Creates a 1-year SP (sp-fabric-mirror-<suffix>) scoped only to your subscription as Reader
  • Adds it as a contained user in contoso_retail with db_owner — just enough to drive change-tracking based mirroring
  • Does the same for the bronze Fabric workspace identity, so workspace-owned objects can talk to SQL too
Wire up private SQL connectivity (VNet Data Gateway + Managed Private Endpoint)

This is the piece that lets Fabric reach Azure SQL over the customer VNet with the firewall closed:

  • Creates a Fabric VNet Data Gateway in the delegated gateway subnet (polls until Live)
  • Creates a gateway-bound SQL connection using the SP, with connection testing enabled so a bad firewall surfaces immediately
  • Grants the Azure SQL server's system-assigned managed identity Contributor on the bronze workspace (required for Fabric mirroring)
  • Creates a Workspace Managed Private Endpoint from bronze to your SQL server, polls the PE connection on the customer side, and auto-approves it
  • Flips publicNetworkAccess=Disabled on the SQL server and removes the deployer's temp firewall rule — from here on all SQL traffic is private
Build the bronze Fabric workspace (lakehouse, mirror, raw shortcut, real-time)

Bronze is the orchestration hub and the landing layer for everything raw:

  • Workspace + workspace identity + contoso_retail_bronze lakehouse
  • Seed notebook populates SQL with a fiscal quarter of data (customers, products, orders, payments, shipments, returns, reviews) and drops 90 days of supplier Parquet + marketing CSV into ADLS raw/
  • SQL Mirror of every retail table into the bronze lakehouse as Delta — near real-time, no pipeline
  • OneLake shortcut Files/raw → ADLS raw/
  • Eventhouse + KQL DB with a Clickstream table; Eventstream CustomEndpoint receives events from the Function emitter and DirectIngests into the KQL Clickstream table
  • Clickstream backfill notebook seeds ~2M historical events into KQL
  • All pipelines live here: weather ingest, bronze / silver / gold initial + incremental loads, and the top-level pl_initial_load / pl_incremental_load medallion orchestrators
Build the silver workspace (raw shortcuts + curated notebooks)
  • silver_raw lakehouse with shortcuts to all 19 bronze mirror tables (Tables/dbo)
  • silver_curated lakehouse with five full-load notebooks: silver_curated_retail_full, silver_curated_weather_full, silver_curated_clickstream_full, silver_curated_hr_full, silver_curated_ops_full — they build conformed dimensions and curated facts
  • Notebooks only — the pl_silver_* pipelines that run them live in the bronze workspace and invoke them cross-workspace
Build the gold workspace (warehouse, semantic models, reports, data agents)
  • Gold warehouse with DDL + sprocs that rebuild the star schema — 9 dims (date, customer, product, store, channel, employee, supplier, warehouse, promotion) and 9 facts (orders, sales, weather_daily, sessions, inventory, payments, returns, reviews, shipments). Every sproc is DROP TABLE IF EXISTS + CTAS, so re-running them is the incremental path
  • Shortcut lakehouse back to silver_curated so the gold sprocs can read curated data via 3-part names
  • Semantic models (Direct Lake): Retail Sales, HR & Workforce
  • Power BI reports: Retail — Sales Overview, Retail — Operations Pulse, HR — Workforce Overview, HR — Attrition & Tenure (organized into Retail / HR folders)
  • Data agents for natural-language Q&A over the gold semantic models
Deploy the clickstream emitter and finish background jobs
  • Deploys the Azure Function via OneDeploy (AAD-authenticated) and wires EVENTHUB_CONNECTION_STRING into app settings
  • Syncs the Flex Consumption triggers so the timer fires (~every 30s, ~50 events/fire)
  • Waits on the parallel background work — seed, backfill, mirror snapshot, gold warehouse create — before declaring done
  • Scales the SQL DB down to GP_S_Gen5_4 for idle-cheap cost while you explore
(Optional) Run the initial medallion load end-to-end

If you leave the auto-run box checked, the script triggers pl_initial_load at the very end. That fans out bronze → silver → gold so the warehouse, semantic models, and reports are populated before the script exits. Uncheck it if you want infrastructure first, then to run the pipeline yourself from the Fabric portal.

When it's done

Open Fabric, browse the three workspaces, run the reports, chat with the data agents, and trigger the incremental pipelines any time to backfill from the last sync up to now (whether that's an hour or five months) and watch it propagate bronze → silver → gold → reports.

When you're done, run teardown.cmd from the same package and it'll tear down everything that was built — MPEs, workspaces, gateway, SP, then the resource group.

Heads up: the gateway subnet's PowerPlatform service association link releases asynchronously, so deleting the resource group can fail with the VNet still attached. If that happens, wait ~1 hour and re-run az group delete --name <rg> --yes (or just click Delete resource group again in the Azure portal). This is normal Azure behavior, not something the teardown script did wrong.
